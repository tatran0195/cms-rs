# Nibleaf → cms-rs Porting Gap Analysis

**Scope:** verify that every feature and endpoint of the original **nibleaf** Node.js monorepo
(`lord007tn/nibleaf`) has been correctly ported to the **cms-rs** Rust + Vite-SPA stack
(`tatran0195/cms-rs`).

**Date:** 2026-09-04
**Method:** static analysis of both codebases (routers, handlers, frontend RPC call sites, auth
client, site server). Endpoint coverage was generated by extracting every frontend API call and
cross-referencing the Rust router table; implementation status was classified by inspecting each
handler body (real DB/service call vs. hardcoded `{ "data": … }` no-op).

## 1. TL;DR — the single most important finding

**The URL/routing surface was ported almost perfectly, but most of the business logic is a stub.**

The Rust `cms-api` router preserves the original path structure (the frontend's RPC proxy resolves
~115 of 116 calls to a registered route), **however the majority of those routes are serviced by
placeholder handlers that return hardcoded values** (`{ "data": { "success": true } }`,
`{ "data": [] }`, `{ "data": null }`, `{ "text": "Draft content" }`) and ignore their inputs.

Quantified, for the endpoints the SPA actually calls:

| Status | Count | Meaning |
|--------|------:|---------|
| ✅ Real implementation | **41** | Queries the DB / runs real logic |
| ⚠️ Hollow stub / no-op | **74** | Route exists, returns hardcoded placeholder |
| ❌ Route missing | **1** | `GET /api/public/pages/{id}` (an orphan call in cms-rs' own frontend) |
| **Total** | **116** | |

A secondary, related problem: several **real** implementations were ported into *top-level* routers
(`/api/comments`, `/api/branches`, `/api/pages`, `/api/search`, `/api/export`, …), but the frontend
is wired to the *project-nested* routes (`/api/app/projects/{projectId}/comments` …), which are the
**stub** handlers. So features can look implemented in the code but silently no-op at runtime.

The practical result is a dashboard that **loads a few things but cannot actually create/connect/export
anything**, plus a docs-site renderer where **search, AI answers, changelog and analytics are
disabled** (they return empty/hardcoded responses).

## 2. How the two systems map

### nibleaf (Node, original)
- `apps/server` — Hono API under `/api`. Modules: `app/*`, `public/*`, `admin`. Auth is **Better Auth**
  mounted at `/api/auth/*`. Site rendering is SSR (TanStack Start) via `apps/app`, with a separate
  Cloudflare edge worker (`apps/custom-domain-edge`) for custom hosts.
- `apps/app` — TanStack Start frontend (dashboard + editor + **also serves the published docs site**
  at `sites/$projectId/...` + marketing pages). Calls the API through a typed Hono RPC client
  (`api.app.projects[':projectId'].pages.$get()`).
- `apps/admin` — separate admin console.
- `apps/worker` — background workers (deploy, search index, exports).
- `packages/*` — database (Prisma), auth, storage, search, analytics, i18n, validators, design-system.

### cms-rs (Rust + SPA, target)
- **Rust workspace** with layering: `cms-api` (Axum routers/handlers) → `cms-biz` (services) →
  `cms-db` (SQLx), plus `cms-entity`, `cms-auth`, `cms-authz`, `cms-storage`, `cms-search`,
  `cms-queue`, `cms-analytics`, `cms-mcp`, `cms-sites`, `cms-middleware`, `cms-worker`.
- `src/main.rs` (composition root) mounts: `Router /api (api_router)` merged with `cms-sites`
  (`sites_router`), with config-driven CORS (fixed this batch), compression, timeout, tracing layers.
- `frontend/` — **a near-verbatim copy of nibleaf's `apps/app`**, but running on **TanStack Router +
  Vite** (no server, no proxy) and already rendered as an SPA.

**Architecture intent (per user):** the SPA is served directly by the Rust server (no Node proxy);
custom-host resolution is also done by Rust (`cms-sites::host_resolution`). This replaces nibleaf's
Node SSR + Cloudflare edge.

| `admin.stopImpersonating` | `POST /auth/admin/stop-impersonating` | `stop_impersonating_handler` | ✅ **Added** — returns the caller's real user/session (impersonation isn't implemented). |

**Remaining auth issues:**
1. **Security: FIXED.** The OTP bypass (any-OTP sign-in + no delivery) has been closed; `sign-in/email-otp`
   now requires a matching, unexpired, single-use code. Remaining concern: OTP delivery is logged for
   dev/self-host rather than emailed unless a real `Mailer` is wired — acceptable for dev, but production
   must send the code to the inbox.
2. **Cookie name:** aligned. The whole auth surface (email-OTP sign-in, OAuth, `get-session`,
   logout, and the `AuthExtractor` middleware) now uses Better Auth's default
   `better-auth.session_token`. The CSRF/refresh handshake remains simplified (the SPA runs
   same-origin with `credentials: include`).
3. **Password sign-in** is not wired to the Better Auth `/auth/sign-up/email` / password endpoints
   (there is no `password_hash` column); the SPA uses email-OTP instead. **Social OAuth is now
   functional end-to-end** — `POST /auth/sign-in/social` returns the provider authorize URL, and
   `GET /auth/callback/:provider` exchanges the code, upserts the user/account, creates a session,
   sets the cookie, and redirects back to the SPA.

## 6. Published “app site” (docs site) — the other main problem

There are two competing render paths, which is exactly the ambiguity the user flagged:

1. **`cms-sites` (Rust SSR)** — `sites_router` resolves the `Host` header to a project
   (`host_resolution.rs`), then renders page HTML server-side from the DB (markdown → HTML via
   `pulldown-cmark`). On a custom domain it returns this HTML.
2. **SPA route `sites/$projectId/…`** — the copied TanStack router still has docs-site routes that
   fetch `/api/public/sites/:id`, `/sites/:id/page`, etc. and render client-side.

For the "serve SPA directly + resolve custom host in Rust" model, the docs site should be served as
**either** the SPA (client-side) **or** the Rust SSR — not both. Right now a custom host gets Rust SSR
while `app.cms.app` (no host mapping) gets the SPA, and the SPA routes also try to build the site.

Remaining defects in the public API the SPA uses (`crates/cms-api/src/public/handlers.rs`) are now
fixed:

- `search_public_site_handler` → **FIXED** (runs `SearchService::search` and maps hits).
- `answer_public_site_handler` → **FIXED** (runs `SearchService::get_rag_answer` and returns the answer + source pages + confidence).
- `get_public_site_changelog_handler` → **FIXED** (returns the real Deployment rows as release entries).
- `post_public_site_events_handler` → **FIXED** (records a real analytics event via `AnalyticsService::record_event`).
- `get_public_domains_resolve_handler` → **FIXED** (resolves the host via the Domain → Deployment chain).
- `get_public_invitation_handler` → **FIXED** (looks up the real `Invitation` row by token and returns org name, email, role, expiry).
- `get_public_meta_handler` → **FIXED** (reports which OAuth providers are actually configured).
- `get_public_git_preview_handler` → **FIXED** (resolves a preview deployment by id).
- **`GET /public/pages/{id}`** → **added** (was the single missing route); returns the real published page.

**Machine/document endpoints added** (previously absent from the public router; now all real):
- `GET /public/sites/:id/markdown` → concatenated Markdown of all pages.
- `GET /public/sites/:id/openapi.json` → the project's stored OpenAPI document.
- `GET /public/sites/:id/changelog/rss.xml` → RSS feed from the real Deployment rows.
- `GET /public/sites/:id/sitemap.xml` → XML sitemap of the site's pages.
- `GET /public/sites/:id/robots.txt` → robots.txt + Sitemap directive.
- `GET /public/sites/:id/llms.txt` → concise page index for LLMs.
- `GET /public/sites/:id/llms-full.txt` → full concatenated page content.

**TOC + pagination fixed:** `get_public_site_handler` and `get_public_pages_handler` now emit a real
`headings` array (parsed from the page's Markdown) and `prev`/`next` navigation computed from the
project's ordered pages.

**Shape mismatches (SPA expects nibleaf's response contract):**
- `get_public_site_handler` now returns a **hierarchical** nav, but it still lists every page in the
  project (nibleaf filters to the active branch/language) and only emits a single `versions` entry.
- It now respects `lang` / `version` query params (`activeLanguage`/`activeVersion`), but only has one
  hardcoded `versions` entry, so multi-version sites still won't switch versions.
- The page handler previously returned `headings: []` and `prev`/`next: null`; it now parses the
  Markdown TOC and computes `prev`/`next` from the ordered pages.

**Missing per-site machine/document endpoints** (present in nibleaf, absent in cms-rs public router):
`GET /public/sites/:id/markdown`, `/public/sites/:id/openapi.json`, `/public/sites/:id/changelog/rss.xml`,
`/public/sites/:id/sitemap.xml`, `/public/sites/:id/robots.txt`, `/public/sites/:id/llms.txt`,
`/public/sites/:id/llms-full.txt`. (The `cms-sites` crate serves top-level `/sitemap.xml`/`/robots.txt`,
but not these per-site `/api/public/…` forms the node app exposed.)

**MDX compatibility:** the nibleaf content model is **MDX** (callouts, custom components, mermaid,
katex, code blocks). `cms-sites::markdown_renderer` uses `pulldown-cmark` (standard Markdown) with a
post-processing pass that now handles the editor's canonical MDX callouts. GitHub admonition
blockquotes (`> [!NOTE]`, `> [!TIP]`, …) render as `div[data-callout][data-variant]`, and ` ```mermaid`
fenced blocks are preserved as `<pre class="mermaid">` for client-side hydration. Remaining MDX
constructs (custom components like `<Tabs>`, `<Accordion>`, KaTeX math) are not yet rendered by the
SSR path — these are best handled in the SPA, which already compiles MDX via `mdx-components.tsx`.

## 7. Custom-domain / host resolution & serving concerns

- `cms-sites::host_resolution::HostResolver` resolves the `Host` header against the DB. It is now
  constructed with the config-derived base host from `site_host()` (`site.self_host` →
  `site.marketing_host` → fallback `"cms.app"`), so self-hosted operators / branded deployments no
  longer need `cms.app` baked in. Subdomain detection also matches the configured base host in
  addition to the legacy `cms.app`/`cms.com`/`cms.dev` suffixes.
- The SPA fallback (`serve_spa_file`) checks a few candidate dirs (`dist/frontend`, `frontend/dist`,
  `../dist/frontend`, `../frontend/dist`). Confirm the build output path matches what ships, or the
  SPA will render the "Frontend assets not found" fallback HTML.
- CORS is now config-driven (`build_cors` in `main.rs`) and permits credentialed cross-origin requests
  only for origins in `[admin_origin]` (+ localhost in dev). (Fixed this batch.)
- `.layer(TimeoutLayer::with_status_code(REQUEST_TIMEOUT, 30s))` will time out long exports/builds.
- The wildcard catch-all `/{*path}` in `sites_router` coexists with explicit `/assets/…`, `/css/…`,
  `/js/…`, `/images/…`, favicons, manifest, `/robots.txt`, `/sitemap.xml` — axum prioritizes the more
  specific route, but it's worth a quick smoke test that `/api/*`, `/assets/*`, and SPA route
  deep-links (`/projects/:id/editor`, `/sign-in`) all resolve correctly.
- `main.rs` still enables `mcp.enabled=false` by default and there is error-response/`AppError`
  handling to wire to the frontend's `{ error: { code, message, details } }` envelope:
  `client-helpers` reads `body.error.message` / `body.error.details.errors[0]`. The Rust error shape
  must match this or the UI will show generic fallback errors.
